# 1. Pin pre-1.0 (0.x.y) direct dependencies

## Status

Accepted

## Context

Post-mortem [2026-05-28 click context crash](https://gitlab2.simplito.com/df/post-mortem/-/blob/main/2026-05-28-click-context-crash.md):
a minor version bump of Typer (0.16 → 0.26) changed internal behavior and broke installs.

Dependencies versioned `0.x.y` are pre-1.0 and may introduce breaking changes in a minor release
(the `x` in `0.x.y`). Without an explicit upper bound, `uv lock` can pick up such a breaking minor
release on the next resolution, even though nothing in `pyproject.toml` changed.

## Decision

Direct dependencies at version `0.x.y` are pinned with `~=0.x.y`, allowing patch releases
(`0.x.y+1`, `0.x.y+2`, ...) but blocking any minor bump (`0.x+1.0`).

- This policy covers only **direct** dependencies (declared in `pyproject.toml`); transitive
  dependencies are left to the resolver.
- Dependencies at `1.0` or later are unaffected and continue to use `>=`.
- Upgrading a pinned dependency past its current minor version is a deliberate action, done via
  a dedicated issue/PR.
- `uv.lock` stays committed to the repository so resolved versions are reproducible.

## Consequences

- Installs are reproducible with respect to pre-1.0 dependencies: a fresh `uv lock` cannot
  silently pull in a breaking minor release.
- Security or bugfix patch releases within the same minor version are still picked up automatically.
- Bumping a pinned dependency to a new minor version requires an explicit `pyproject.toml` change
  instead of happening implicitly on the next lock.
